# brain-plot 使用者体验与期刊配图审查

审查日期：2026-09-26。对象：本地仓库提交 `c5c033b84af432dc52912c64a85fe1a5315afd4d`，origin 为用户提供的 GitHub 仓库。GitHub 网页及 raw 地址本次读取失败，未确认远端是否另有更新。本报告不更改绘图实现和既有用户规则。

## 判断

这是一个具有较好科学约束和出图基础的个人工作流；推广给同事使用、交付期刊最终文件之前，应优先补齐输入身份、微状态计算边界与最终交付验证。主要问题不在于美观程度，而在于“用户以为画的是哪个结果”“不同图中的标签是否仍指同一个状态”“修订后能否复现”。

已具备的优点：被试内先平均、被试间等权；数据单位和时间网格等一致性检查；ERP 地形图与波形使用同一条件和窗口；ERP 共享对称色标并考虑插值极值；固定物理画布；可编辑 SVG；版本归档；图注事实及运行记录；合成数据回归与部分几何检查。

注意：不显示电极点、默认无 SEM、固定个人配色、只导出 PNG/SVG、不询问统计和窗口来源等，都是仓库明确记录的个人选择。它们本身不构成实现错误。以下分别标记代码缺陷、科学使用风险和产品扩展建议。

## 优先修复的问题

### 1. P1：微状态条件同名会静默丢失数据

位置：`microstate_plot.py:164–175`，`check()` 未校验显示名。

`cells_of()` 使用显示名称而不是条件键作为字典索引。输入 `{"A":"Same","B":"Same"}` 被验证函数接受，但返回的 cells 只剩一个，且其数据来自 B。这会让用户拿到一张看似正常、实际少条件的图。`per_group` 分支也使用拼接的显示文字作键。

建议：内部始终用条件键/组键的组合标识数据，显示名只用于文本。若需要最小修复，先明确拒绝重名标签；同时添加实际绘制条件数与请求条件数的核验。

验收：两个原始条件永不因为改显示名而合并；每个请求条件都有且仅有一个对应面板。

### 2. P1：模板缺少通道名时，无法保证空间对应关系

位置：`microstate_plot.py:75–100`。

没有 `ch_names` 的模板只核对列数。独立复现中，同一个匿名三列模板分别配 `[Fz,Cz,Pz]` 和 `[Pz,Cz,Fz]` 均被接受，数组不重排。若模板与 FIF 通道顺序实际不同，图和状态分配都可能错误，而且不报错。

这是文档允许的行为，但作为科研工具接口仍有明显风险。建议新模板要求 `ch_names`；旧格式通过一次明确的通道顺序映射转换，并记录映射来源。不能只用“通道数相等”替代身份核验。

验收：带名称模板任意列重排后结果不变；匿名模板在没有明确顺序依据时不能被自动解释。

### 3. P1：微状态“只画图”的定位与实际计算范围不一致

位置：`microstate_plot.py:110–139,164–175,272–281`；`SKILL.md` 微状态分支。

程序确实不重新聚类，但会对 grand average 重新进行平均参考、空间归一化、模板匹配、短段合并和状态重编号。默认参数包括 `polarity=sensitive`、`min_segment_ms=30`。这些步骤决定状态序列和持续时间，属于结果生成环节。

风险是：用户提供“同一组模板”不等于程序复现了分析软件的 segmentation。grand-average segmentation 也不等于个体 segmentation 的平均，不能直接当作个体层面持续时间或组差异证据。现有图注写明了算法，这是优点，但不能代替两套方法实际一致的验证。

建议优先支持读取上游保存的 `labels/times/template IDs` 并直接呈现。现有算法可保留为明确命名的派生计算模式；有明确上游配置时自动读取，没有时只询问必要参数，不能把科学参数默认值当成用户研究方法。图注直接标注这是 grand-average segmentation。

验收：直接呈现模式中的序列与上游文件逐样本一致；派生模式有独立、已知真值的算法验证，并记录算法和参数来源。

### 4. P2：微状态边界、时段事实和辅助竖线不一致

位置：`microstate_plot.py:142–152,258–263,352,367–368,403–405`。

复现：采样时刻 `[0,4,8,12] ms`，标签 `[0,0,1,1]`。色带第一段为 `0–6 ms`，第二段为 `6–14 ms`；`spans` 却写成 `0–8`、`8–16 ms`；蝶形图辅助竖线位于 `8 ms`。`labels_ms` 又记录首末采样中心。它们可以分别作为不同定义存在，但目前没有清晰区分，且与 MS2 的统一边界要求不符。

建议以样本索引为唯一基础，分别命名采样中心与绘图边界，所有绘图元素共享同一边界函数；图注中的持续时间使用明示的定义。

验收：竖线、色带、GFP 填色边界严格对齐；运行记录注明端点语义；首末段有专门测试。

### 5. P2：状态排序公式不等于规则描述

位置：`microstate_plot.py:155–161`。

规则说按“最长段中点的中位数”排序，实现是“起点中位数与终点中位数的平均”。两者一般不相等。

复现：一个状态的三段分别为 `(0,100),(40,50),(60,70)`，中点中位数是 50，实现算出 55；另一状态的中点为 52，实际排序因此反转。

建议先按每个面板计算中点，再取中位数。同时允许沿用上游状态名称和固定映射：不要每换一组条件，就让 S1 在不同论文图里代表不同模板。

验收：上述例子顺序符合 MS4；改变图中条件子集时，固定身份模式下模板 ID 与颜色不变。

### 6. P2：`inspect` 不覆盖绘图支持的输入布局

位置：`erp_plot.py:228–254,427–449`。

`plot/load` 支持 `<condition>/<group>/<subject>-ave.fif`，但 `inspect` 仅用 `find_groups`。这种布局得到 `{'all': []}`，随后在取第一个文件时报 `IndexError`。这发生在 skill 推荐流程的第一步。Evoked 的 trials 摘要还只统计第一份文件，而非所有被试。

建议共用输入发现逻辑；无文件时给出可操作错误；inspect 给出全体条件和被试的检查摘要，并标明仅从首文件读取的字段，避免用户误以为所有输入已验证。

验收：README 列出的每种输入布局都能 inspect；跨被试 nave 不同会反映在汇总中；空目录不出现 traceback。

### 7. P2：常见被试文件名会发生身份碰撞

位置：`erp_plot.py:224–225`。

实测 `sub-01_task-erp-ave.fif`、`sub-02_task-erp-ave.fif` 都解析成 `sub`。后续重复检查会停止，因此通常不会静默合并，但用户必须重命名文件才能继续。

建议保留现有简单命名，同时识别 `sub-<ID>`；更复杂的旧数据用小型 manifest 明确映射 subject/group/condition/path。不要要求用户为了出图改动原始文件名。

验收：sub-01 与 sub-02 区分；真实重复仍被拒绝；排除清单与图注使用相同 ID。

### 8. P2：分组微状态布局存在走不通的错误建议

位置：`microstate_plot.py:63–66,286–294`。

两条件×两组，`per_group=true` 会产生四个 cells，要求提供 grid；但验证器明确拒绝 `per_group` 与 grid 同时使用。用户按错误信息操作仍无法完成。

建议支持条件×组 cell 的布局，或明说当前不支持并自动建议“每组一张”。模板-only/by-K 用户也不应在仅想展示已有模板时被迫提供 epoch 和分段窗口；可以独立支持模板+montage 的静态图。

验收：2×2 组设计有清晰可执行路径；错误信息不指向被校验器禁止的组合。

### 9. P2：颜色检查会漏掉完全相同的颜色

位置：`erp_plot.py:78–93`。

`colour_check` 先对颜色去重。实测 `['red','red']` 的最小色差为 Infinity，既不报警，也不能反映两条同色实线完全不可区分。单一颜色还会把非标准 JSON 数值 `Infinity` 写入记录。

但同色不同线型本来可以合法编码因素，所以也不能简单禁止重复色。建议检查最终颜色+线型编码；重复且同线型才提示不可区分。单一类别使用 `null/not_applicable`，序列化禁止非有限数字。

验收：同色同线型被识别；同色虚实线保留；run 文件可以通过严格 JSON 解析器。

### 10. P2：可复现记录尚未覆盖决定结果的全部输入

位置：`erp_plot.py:363–366,1001–1012`；`microstate_plot.py:514–519`。

FIF 记录路径、大小和 mtime，微状态模板只记录路径；微状态代码摘要不包含导入的 erp_plot.py；配置只保留显式字段，默认值和完整依赖环境不完全展开。上游模板在原路径替换后，仅凭旧 run 难以核实原图来源。

建议最终输出时保存输入和模板内容摘要、两份脚本版本/摘要、resolved spec、实际字体、完整必要版本、状态原始 ID 到显示 ID 的映射。缓存仍可用快速元数据判定，最终 provenance 单独使用内容摘要；无需每次都增加不必要的重算。

验收：模板内容变化会产生不同摘要；缺省参数升级后仍可从旧 run 还原旧设置；更改依赖脚本可追踪。

## 从作者和读者角度优化期刊图

### 现有示例的具体评价

- ERP 示例：波形/地形图对应、共享色标、颜色×线型编码是优点。但 6 条曲线加 12 张地形图信息较密，N400 灰窗在全 epoch 中占比有限。若核心论点是该窗的条件差异，可另加经作者同意的聚焦面板，并保留全 epoch 概览。不要自动裁掉其他活动。
- ERP 刻度会自动放到横轴不同侧，避免遮挡但增加跨面板比较负担。可以提供常规底部时间轴作为可选投稿样式。它属于设计取舍，不是数据错误。
- 微状态 GFP 示例比蝶形图更容易读出时间结构；蝶形图适合需要交代全部通道变化的读者。建议让图的科学目的决定保留哪个，不默认堆叠所有内容。
- 微状态 S4 青色与 S5 紫色在仓库自己的色觉模拟测试中已被识别为可能混淆（test_microstate.py:104–109）。目前规则要求不提醒。这是个人默认的取舍；投稿检查可单独显示模拟预览，状态编码不应仅依赖颜色。
- 微状态模板经过平均参考和单位范数归一化。图注应直说“归一化模板，无量纲”，不能让读者把它当作 ERP 地形图的 µV 振幅。当前无色条并非必然错误，但含义需明确。
- 状态文字着色、复合图无面板字母是可配置样式问题。Nature 的官方图指南要求多面板标识，并强调可编辑文字和可访问配色；现有个人样式不能直接被称为该刊合规。[Nature 图形规范](https://research-figure-guide.nature.com/figures/preparing-figures-our-specifications/)

### 投稿交付建议

1. 保留目前 house style 和 PNG/SVG 默认；额外提供用户明确选择的 submission export。没有必要重新把“你投什么期刊”变成每次必问的问题。
2. 针对目标刊物核验最终尺寸、字体、格式、分辨率。不能用“600 dpi”替代全部投稿要求：Elsevier 的通用说明推荐 PDF/EPS/TIFF/JPEG，并区分不同 artwork 类别的分辨率；具体期刊仍应以自己的作者指南为准。[Elsevier 格式说明](https://www.elsevier.com/about/policies-and-standards/author/artwork-and-media-instructions/artwork-overview)；[尺寸与分辨率](https://www.elsevier.com/about/policies-and-standards/author/artwork-and-media-instructions/artwork-sizing)
3. 默认 180 mm 图缩到 90 mm，6 pt 文字会变成 3 pt。应按最终宽度重排并保持字号，不应靠缩图适配单栏。
4. 提供必要的共享轴范围/色标选项，服务多幅论文图的直接比较；现有每图自动范围继续可用。不要为了使弱图显色而暗中改变共享尺度。
5. 加最终文件预检：文字与图层可编辑性、嵌入位图分辨率、字体替代、画布外元素、面板字母、灰度/色觉模拟。PNG 人眼检查继续保留，但不能证明 SVG 导入后仍正常。
6. 将图注事实与作者确认后的英文图注草稿分开交付；草稿只组织已知事实，缺失方法不补写。继续保留不自动生成显著性结论的边界。

## skill 交互与维护

- **访谈应按缺失信息，而不是固定回合数推进。** 当前已有“只问读不到的信息”的良好原则；进一步明确：完整 spec 或分析计划已经给出时跳过相应轮次，仅汇总确认尚未授权的科学选择。用现有许可决定是否需要再次确认，避免已授权的重复出图仍逐项问答。
- **科学值与视觉值分开处理。** 未知模板极性、上游 segmentation 算法会改变结果，需要依据；颜色、字号等可延用已认可默认。不要因为都叫“参数”而一律默认或一律询问。
- **修正文档自相矛盾。** SKILL.md:25 仍要求说明窗口来源，而规则 S3 明确可选且不询问。主流程说不要手工 restyle，而 T5 又说 SVG 用于手动调整；应说明代理通过 spec 改图，用户编辑后的最终文件另存并记录，不能声称旧 QA 覆盖新文件。
- **减少环境摩擦。** README 建议虚拟环境；增加轻量 `doctor` 输出 Python、依赖版本、可用字体、输入/输出目录。`CLAUDE.md` 的专用 SendUserFile 指令应提供平台可用的展示方式；复制安装 skill 时还需考虑 `../examples` 不随单个 skill 文件夹一起分发。
- **错误信息指向解决动作。** 缺 montage、通道不一致、未应用投影、输出路径不可写等都应保持严格，但说明上游应该准备什么。真实个体 digitization 不同的数据集当前会因严格 contract 拒绝，应明确这是输入兼容范围，不直接把所有拒绝等同于数据质量问题。
- **完善维护证据。** 当前两套回归已覆盖许多绘图几何问题，但没有检查上述身份/语义案例。`evals/cases.md` 是手工用例清单，尚不能替代 fresh-session 执行记录。增加受支持稳定版本组合的 CI；测试输出在临时目录；不要只在一个 MNE dev 环境通过就推断所有 `mne>=1.6` 可用。`common_sphere` 调用 MNE 私有函数，升级兼容尤其值得验证。

## 建议实施顺序

| 阶段 | 工作 | 完成标准 |
|---|---|---|
| 第一批：结果可信 | 条件 ID、模板通道身份、状态边界与排序、inspect/ID/分组布局 | 本报告复现用例进入回归且全部通过；已有两套回归仍通过 |
| 第二批：方法可追溯 | 读取上游 labels；派生计算明确命名；内容摘要、resolved spec、固定状态映射 | 每个图形元素都能追溯到输入结果，跨图状态身份稳定 |
| 第三批：投稿可交付 | 可选投稿导出、最终尺寸检查、颜色/字体/面板预检 | 选定一种实际期刊要求，以最终上传文件完成一次端到端验收 |
| 第四批：同事可上手 | 合并缺失信息访谈、doctor、完整安装示例、agent eval 执行记录 | 新使用者从干净环境与示例数据完成出图，错误均有可执行解法 |

暂不建议优先扩展到源定位、时频、更多聚类算法或复杂 UI。差异波等新增能力可在真实需求出现后独立设计，避免削弱目前清晰的范围。应先把已有 ERP 与微状态路径做到稳定、可理解、可复核。
